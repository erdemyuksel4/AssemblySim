## Page 3

Introduction
The concept of instruction sets refers to the set of all commands a microprocessor
understands and can execute. These instructions are the building blocks of machine-
level programming and provide the fundamental capabilities to manipulate data, control
execution, and interface with hardware.
Understanding addressing modes is crucial, as it defines how the processor identifies
the operands (data or memory locations) required by an instruction. This presentation
explores various addressing methods, including immediate, direct, indirect, register, and
displacement addressing modes.

## Page 4

What is an 
Instruction 
Set?
An instruction set is a collection of 
machine instructions that a CPU can 
execute directly. Each instruction
consists of an operation code
(opcode) and, in some cases, 
operands that specify the data to be 
processed or the memory locations
involved.
The instruction set architecture
(ISA) defines the design and
operational behavior of a CPU. It
includes instructions for arithmetic
operations, data movement, program 
control, and logic operations. The
efficiency of a processor heavily
depends on its instruction set.

## Page 6

What are Addressing Modes?
Addressing modes define how the processor finds the operands needed by the
instructions. An operand can be a value, a register, or a memory location, and the
addressing mode determines how this operand is accessed.
Each instruction can use one or more addressing modes, and different architectures
may support different sets of addressing modes. The most common ones include
immediate, direct, indirect, register, and displacement addressing.

## Page 8

Immediate 
Addressing
In immediate addressing, the operand
is a constant value provided directly in 
the instruction itself. This value does
not require any additional memory
access, making this addressing mode
very fast and efficient for small, fixed
values.
However, immediate addressing is 
limited by the size of the operand field
in the instruction, meaning it can only
handle a specific range of values. It is 
most commonly used for initializing
registers or performing arithmetic
operations.

An example of immediate addressing could
be the instruction:
• MOV AX, 5
Here, the value 5 is directly encoded in the

This addressing mode is efficient when the
value is known beforehand and does not 
change during program execution.

## Page 10

Direct 
Addressing
In direct addressing, the address of the
operand is specified explicitly in the
instruction. The CPU directly accesses
the memory location to retrieve the
operand. While this addressing mode is 
simple to use, it requires one additional
memory access to fetch the operand, 
which can slow down execution
compared to immediate addressing.

An example of direct addressing:

Here, the instruction tells the CPU to move

## Page 12

Indirect
Addressing
In indirect addressing, the memory
address of the operand is stored in a 
register. The instruction contains a 
reference to this register, and the CPU 
retrieves the operand by accessing the
memory location stored in the register.
This addressing mode adds flexibility
because the memory location can 
change dynamically during execution, 
unlike direct addressing, which has a 
fixed memory location.

## Page 14

Register 
Addressing
In register addressing, the operand is 
stored directly in one of the CPU's
registers. This is one of the fastest
addressing modes since no memory
access is required.
The size and number of registers are
limited, but register addressing is ideal 
for frequently accessed data and
intermediate results in arithmetic or
logical operations.

The displacement value allows the

locations relative to a base address,

CISC vs. RISC Instruction Sets
In CISC (Complex Instruction Set Computing) architectures, instruction sets tend to
have a large number of instructions and complex addressing modes. This allows for more
flexible and powerful operations at the expense of speed and efficiency.
In contrast, RISC (Reduced Instruction Set Computing) architectures focus on a small
number of simple instructions, each executed very quickly. This trade-off simplifies
processor design but may require more instructions to perform complex tasks.

CISC architectures, such as Intel's

The simplicity of RISC instructions often
results in more efficient pipeline
processing, allowing for better overall
performance in high-speed
applications.
