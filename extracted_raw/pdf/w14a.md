## Page 2

INTRODUCTION 
TO MEMORY 
HIERARCHY 
Memory hierarchy is a structured
arrangement of different types of 
memory in a computer system
designed to optimize performance
and efficiency. It includes registers, 
caches, main memory (RAM), and
secondary storage.


---

## Page 3

PURPOSE OF 
MEMORY 
HIERARCHY 
The primary purpose of memory hierarchy is to
balance the trade-offs between speed and cost. 
Faster memory types (like registers and caches) 
are smaller and more expensive, while slower
types (like hard drives) are larger and cheaper.

## Page 6

CACHE 
MEMORY 
OVERVIEW 
Cache memory is a small-sized type of volatile
computer memory that provides high-speed data 
access to the processor. It stores copies of 
frequently accessed data from main memory to
reduce latency during data retrieval.


---

## Page 7

LEVELS OF CACHE 
Caches are typically 
organized into levels:
L1 Cache: Smallest, 
fastest cache located 
closest to the CPU 
cores.
L2 Cache: Larger 
than L1 but slower; 
acts as a secondary 
cache.
L3 Cache: Shared 
among cores; larger 
but slower than L2.

## Page 8

CACHE DESIGN PRINCIPLES 
Key principles in cache 
design include:
Locality of 
Reference: Programs 
tend to access a relatively 
small portion of their 
address space repeatedly.
Cache Size: Balancing 
size with speed; larger 
caches can store more 
data but may increase 
access time.
Block Size:The amount 
of data transferred 
between cache and main 
memory during a cache 
miss.


---

## Page 9

LOCALITY OF REFERENCE EXPLAINED
Locality of reference 
refers to the tendency of 
programs to access a 
small set of memory 
locations repeatedly over 
time:
Temporal 
Locality: Recently 
accessed items are likely 
to be accessed again 
soon.
Spatial Locality: Items 
near recently accessed 
addresses are likely to be 
accessed soon.

## Page 11

DIRECT-MAPPED 
CACHE 
In direct-mapped caching, each block from
main memory maps to exactly one cache line. 
This approach is simple but can lead to high
contention for cache lines.


---

## Page 12

FULLY 
ASSOCIATIVE 
CACHE 
In fully associative caching, any block can be placed
in any line of the cache. This flexibility reduces
contention but increases complexity due to the
need for searching through all cache lines.


---

## Page 13

SET 
ASSOCIATIVE 
CACHE 
Set associative caching combines elements of 
both direct-mapped and fully associative
caches by dividing the cache into several sets, 
each containing multiple lines. A block can be 
placed in any line within its designated set.


---

## Page 14

REPLACEMENT POLICIES OVERVIEW
Replacement policies 
determine which cache 
entry should be replaced 
when a new block is 
loaded into the cache:
Least Recently Used 
(LRU)
First In First Out 
(FIFO)
Random Replacement


---

## Page 15

LEAST 
RECENTLY USED 
(LRU) 
The LRU policy replaces the least recently used
block when new data needs to be cached. It
relies on the assumption that blocks used
recently will likely be used again soon.


---

## Page 16

FIRST IN FIRST 
OUT (FIFO) 
FIFO replaces the oldest block in the cache
regardless of how often it has been accessed. 
This method is simple but may not always yield
optimal performance.


---

## Page 17

RANDOM 
REPLACEMENT 
POLICY 
The random replacement policy randomly
selects a block to replace when new data is 
cached. While it may not be as efficient as LRU 
or FIFO, it is easy to implement and can 
perform well in certain scenarios.


---

## Page 18

WRITE POLICIES OVERVIEW 
Write policies 
dictate how 
updates to cached 
data are handled:
Write-Through
Write-Back


---

## Page 19

WRITE-
THROUGH 
POLICY 
In write-through caching, every write operation
updates both the cache and main memory
simultaneously, ensuring data consistency but 
potentially increasing latency due to more
frequent writes.


---

## Page 20

WRITE-BACK 
POLICY 
In write-back caching, updates are made only in the
cache initially; changes are written back to main 
memory later when the block is evicted from the
cache. This approach reduces write latency but 
requires careful management to maintain
consistency.


---

## Page 21

IMPACT OF CACHE MISSES 
Cache misses occur when requested data is not found in the cache, leading to delays
as data must be fetched from slower levels of memory or storage. There are three
types:
1. Compulsory Misses
2. Capacity Misses
3. Conflict Misses


---

## Page 22

COMPULSORY 
MISSES 
EXPLAINED 
Compulsory misses (or cold misses) happen
when data is accessed for the first time and
must be brought into the cache from main 
memory.


---

## Page 23

CAPACITY 
MISSES 
EXPLAINED 
Capacity misses occur when there is insufficient
space in the cache to store all active data blocks
required by a program, leading to evictions
even though some blocks may still be useful.


---

## Page 24

CONFLICT 
MISSES 
EXPLAINED 
Conflict misses arise in direct-mapped or set-
associative caches when multiple blocks
compete for the same cache line, causing
evictions even if other lines are available.


---

## Page 28

CACHE 
COHERENCE 
PROTOCOLS 
Cache coherence protocols ensure that all cores
have consistent views of shared data by
managing how changes made by one core are
propagated to others:
1. MESI Protocol (Modified, Exclusive, Shared, 
Invalid)
2. MOESI Protocol (adds Owned state)


---

## Page 29

MESI PROTOCOL 
EXPLAINED 
The MESI protocol helps maintain coherence by
defining states for each cache line that indicate
whether it contains valid data and whether that
data is modified or shared with other caches.


---

## Page 30

PARALLEL PROCESSINGTECHNIQUES
Parallel processing techniques enable efficient utilization of multi-core architectures:
1. Single Instruction Multiple Data (SIMD) - Executes the same instruction on multiple 
pieces of data simultaneously.
2. Multiple Instruction Multiple Data (MIMD) - Allows different instructions on 
different cores operating independently on different data streams.


---

## Page 31

SIMD 
ARCHITECTURE 
OVERVIEW 
SIMD architectures enhance performance for
tasks that involve large datasets by applying
vectorized operations across multiple data 
points simultaneously, making them ideal for
applications like graphics processing and
scientific computations.


---

## Page 32

MIMD 
ARCHITECTURE 
OVERVIEW 
MIMD architectures allow independent
execution streams across multiple cores, 
enabling diverse workloads such as running
multiple applications or handling complex task
scheduling dynamically based on system
demands.


---

## Page 33

HYPER-
THREADING 
TECHNOLOGY 
Hyper-threading allows a single physical CPU core
to appear as two logical cores to an operating
system, improving resource utilization by allowing
two threads to run simultaneously on one core.


---

## Page 34

SIMULTANEOUS 
MULTITHREADING 
(SMT) 
SMT extends hyper-threading capabilities
further by allowing multiple threads per core
while optimizing resource sharing among them, 
enhancing throughput without significant
overhead.
